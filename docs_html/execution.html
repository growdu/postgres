执行引擎

Portal — 查询执行上下文

Portal — 游标/执行上下文，封装一条或多条语句的执行状态
  • CreatePortal("", true,true) — 创建无名 Portal（exec_simple_query 用）
  • visible = false — 不在 pg_cursors 中显示
  • strategy — 决定执行模式（PORTAL_ONE_SELECT / PORTAL_MULTI_QUERY 等）
  • stmts — List<PlannedStmt> 要执行的语句列表
  • portalContext — Portal 私有内存上下文
  • holdStore / holdSnapshot — WITH HOLD 游标保留数据

PortalRun() — 分发执行 (pquery.c:685)

PortalRun(Portal portal, long count, bool isTopLevel, DestReceiver *dest, DestReceiver *altdest, QueryCompletion *qc)
  • 设置 Portal 激活状态和资源所有者
  • 根据 portal->strategy 分发到不同执行路径
  • TRACE_POSTGRESQL_QUERY_EXECUTE_START/DONE 追踪点
  • log_executor_stats 统计执行耗时

PORTAL_ONE_SELECT

PortalRunSelect
单条 SELECT，使用 tuplestore 缓冲结果

PORTAL_ONE_RETURNING

FillPortalStore + RunSelect
带 RETURNING 的单条语句（INSERT/UPDATE/DELETE）

PORTAL_ONE_MOD_WITH

FillPortalStore + RunSelect
带 CTE 的单条修改语句

PORTAL_MULTI_QUERY

PortalRunMulti
多语句或非 SELECT 类查询（最常用）

PortalRunMulti() — 多语句执行 (pquery.c:1185)

遍历 portal->stmts 列表

  • 每条 PlannedStmt 单独处理
  • CHECK_FOR_INTERRUPTS() 中断检查

plannable query（utilityStmt == NULL）

  • GetTransactionSnapshot() 获取事务快照（首次）或 UpdateActiveSnapshotCommandId()（后续）
  • ProcessQuery(pstmt, sourceText, params, dest, qc)
  • log_executor_stats 记录耗时

utility query（CMD_UTILITY）

  • PortalRunUtility() 处理（不设置快照）
  • VACUUM / CREATE INDEX / GRANT 等直接执行

收尾

  • CommandCounterIncrement() 命令计数递增
  • MemoryContextDeleteChildren() 清理临时内存
  • PopActiveSnapshot() 弹出快照

ProcessQuery() — 单查询执行 (pquery.c:137)

ProcessQuery(PlannedStmt *plan, const char *sourceText, ParamListInfo params, DestReceiver *dest, QueryCompletion *qc)
  • CreateQueryDesc() — 创建 QueryDesc（封装 plan + snapshot + dest）
  • ExecutorStart() — 初始化执行器状态（ExecInitNode 树）
  • ExecutorRun() — 驱动执行（ForwardScanDirection 扫描）
  • ExecutorFinish() — 完成处理（FINAL 扫描）
  • ExecutorEnd() — 清理资源（ExecEndNode 树）
  • SetQueryCompletion() — 设置命令完成标签（SELECT/INSERT/UPDATE/DELETE）

执行器核心 API (executor/execExpr.c / execMain.c)

ExecutorStart(QueryDesc *queryDesc, int eflags)
  • 创建 EState（执行器状态）
  • 调用 ExecInitNode() 递归初始化 Plan 树
  • 建立 tuple table / scan descriptor / 聚合状态
  • eflags 控制是否启用模糊游标/只读
ExecutorRun(QueryDesc *queryDesc, ScanDirection direction, uint64 count)
  • 从根节点向下驱动执行树
  • ScanDirection: ForwardScanDirection / BackwardScanDirection
  • count = 0 表示全部执行
  • 结果通过 DestReceiver 输出到客户端
ExecutorFinish() / ExecutorEnd()
  • Finish: 执行器后处理（FINAL 节点处理）
  • End: 调用 ExecEndNode() 逐层清理，释放资源

DestReceiver — 结果输出目标

DestReceiver — 接口，将执行结果路由到不同目的地
  • DestRemote — 通过扩展协议发送给客户端
  • DestSimple — 简单输出（psql 控制台）
  • DestNone — 丢弃结果（如规则展开的附加查询）
  • DestSPI — SPI（存储过程/函数）内部调用
  • DestTuplestore — 结果存入 tuplestore（游标）

执行计划节点树

PlannedStmt.planTree — Plan 节点树，递归执行
  • 扫描节点：SeqScan / IndexScan / IndexOnlyScan / BitmapScan / TidScan / SubqueryScan
  • 连接节点：NestedLoop / HashJoin / MergeJoin
  • 聚集节点：Aggregate / HashAggregate / GroupAggregate / WindowAgg
  • 结果节点：Result / Append / MergeAppend
  • 修改节点：ModifyTable / Insert / Update / Delete / Merge
  • 控制节点：Sort / Limit / Unique / Material / Memoize / Gather
