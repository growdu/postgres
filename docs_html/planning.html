入口函数

pg_plan_queries() postgres.c:971

  • planner_hook 支持自定义规划器
  • 默认调用 planner()
  • log_planner_stats 统计规划耗时

planner() — 入口点 (planner.c:287)

planner(Query *parse, const char *query_string, int cursorOptions, ParamListInfo boundParams)
  • 调用 standard_planner() 完成实际规划
  • planner_hook 允许外部自定义（e.g. pg_plan_hint）
  • 返回 PlannedStmt，其中 planId 用于 pg_stat_statements

standard_planner() — 核心规划器 (planner.c:303)

Step 0: 初始化 PlannerGlobal

  • 创建 PlannerGlobal 共享状态结构
  • 设置 boundParams / subplans / relationOids 等
  • 评估并行可行性（parallelModeOK / parallelModeNeeded）
  • 判断 cursor_tuple_fraction（游标 vs 全量）

Step 1: subquery_planner() — 子查询规划和上拉

subquery_planner(glob, parse, NULL, false, tuple_fraction, NULL)
  • flatten 包含的 CTD（WITH 子句）
  • 上拉子查询（subquery push-down）
  • 构建 RelOptInfo 表连接图
  • 处理 GROUP BY / DISTINCT / HAVING / window functions
  • 产生最终的 root->final_rel（FINAL upper rel）

Step 2: fetch_upper_rel + get_cheapest_fractional_path

  • 获取 UPPERREL_FINAL 关系（最顶层）
  • 从已生成的 Path 集合中选择代价最低的路径
  • Path 表示一种可执行的连接顺序/算法

Step 3: create_plan() — 将最优 Path 转为 Plan

create_plan(root, best_path) planner.c:441
  • 递归构建从叶子扫描到根节点的执行计划树
  • 生成 SeqScan / IndexScan / NestedLoop / HashJoin 等节点
  • 附加 Sort / Limit / Aggregate / Gather 等上层节点

Step 4: 可选添加 Gather（并行查询）

  • debug_parallel_query = on/regress 时强制添加
  • 判断 top_plan->parallel_safe && initPlan 条件
  • Gather 节点启动 worker 进程执行子计划

subquery_planner() 内部流程

subquery_planner(PlannerGlobal *glob, Query *parse, RelabelInfo *relabel, bool hasOuterJoin, double tuple_fraction,PlannerInfo *parent_root)
  • scope_wrap：处理 CTD（WITH）包装
  • flatten_graph：展平 WITH RECURSIVE 等
  • preprocess_features：预处理（常量折叠、IN 变 ANY 等）
  • pull_up_subqueries：子查询上拉（减少嵌套）
  • reduce_outer_joins：化简外连接
  • make_relarrays：构建 RelOptInfo 集合
  • set_base_path_clauses：为每个表设置约束条件
  • make_one_rel：对每个关系生成 RelOptInfo
  • find_minimax_clauses：处理 MIN/MAX 优化
  • choose_best_plan：评估路径代价，选择最优

输出：PlannedStmt

PlannedStmt — 执行计划树根节点
  • commandType — CMD_SELECT / CMD_INSERT / etc.
  • canSetTag — 是否可设置命令标签
  • planTree — Plan 节点树（核心执行计划）
  • rtable — 范围表（所有访问的关系）
  • resultRelation — 修改操作的目标表
  • utilityStmt — CMD_UTILITY 时非空
  • queryId — 继承自 Query 的归一化 ID
  • planId — 计划级 ID（pg_stat_statements）
