pg_rewrite_query() (postgres.c:799)

pg_rewrite_query(Query *query)
区分 CMD_UTILITY 和普通查询的重写路径
  • CMD_UTILITY → 直接返回 list_make1(query)（不重写）
  • 普通查询 → QueryRewrite(query)
  • 支持 Debug_print_parse 打印 parse tree
  • 支持 Debug_copy_parse_plan_trees / Debug_write_read_parse_plan_trees 调试

QueryRewrite() — 三步重写 (rewriteHandler.c:4566)

Step 1: RewriteQuery — 应用非 SELECT 规则

RewriteQuery(parsetree, NIL, 0, 0) rewriteHandler.c:3882
  • 扫描 Query.rtable 中每个表的规则（pg_rewrite 系统表）
  • 处理 INSTEAD / QUAL_INSTEAD / ALSO 规则
  • INSTEAD 规则完全替代原操作；ALSO 规则附加执行
  • 一个查询可能被展开为多个（规则展开）

Step 2: fireRIRrules — 应用 RIR (Rule Instead of Row) 规则

fireRIRrules(query, NIL) rewriteHandler.c
  • 对每个 rewritten query 应用行级 INSTEAD 规则
  • 遍历 jointree 找到每个 base relation 应用 RIR 规则
  • 适用于 CREATE RULE ... DO INSTEAD 针对单行的规则
  • 每个 Qualified 规则展开为独立 subquery

Step 3: 标记 canSetTag

  • 如果原始查询仍在结果列表中 → 原始查询设置标签
  • 如果原始查询不在 → 最后一个同类型 INSTEAD 查询设置标签
  • 确保命令完成标签正确归属

RewriteQuery() 详解 (rewriteHandler.c:3882)

RewriteQuery(Query *parsetree, List *rewrite_events, int orig_rt_length, int rt_index)
  • 遍历 parsetree 的每个 RangeTblEntry，查找 pg_rewrite 中的规则
  • 对于每个规则，生成 rule action 并展开到 query
  • 规则条件（WHERE clause）被合并到规则动作中
  • 递归处理子查询（subquery 中的规则）
  • 使用 AcquireRewriteLocks() 确保规则引用的表被正确锁定

规则类型

INSTEAD — 完全替代
  • 原语句被完全替换为规则动作
  • 常用于实现自动更新视图
ALSO — 附加执行
  • 原语句正常执行，规则动作额外执行
  • 可用于审计、触发器模拟
QUAL_INSTEAD — 条件替代
  • 满足条件时替代，否则执行原语句
  • 条件通过 AND 合并到规则动作的 WHERE 中

重要约束与特性

  • QueryRewrite() 仅应用于 QSRC_ORIGINAL 查询（来自解析器）
  • 重写后保留 queryId 用于 pg_stat_statements
  • 多语句 SQL（分号分隔）各自独立重写，但共享事务
  • 规则展开可能导致单查询 → 多查询（需返回 List）
  • CMD_UTILITY 跳过重写（CREATE INDEX / VACUUM / GRANT 等）
